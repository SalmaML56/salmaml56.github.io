I'm an AI Engineer working across agentic AI, RAG, NLP and backend engineering. I choose the approach that fits the problem, whether that is a classical model, deep learning or an LLM, and then I own the work from data preparation to a running service.

Right now I work on long-running AI agents at Quantlix. Before that I built a multi-tenant SaaS platform, a healthcare kiosk and a delivery-time model. The unglamorous middle is where I spend most of my time: indexes, latency, safety layers, auth and compliance.

I only call something done after I've seen it work: a live request, a trace, a log line.

Wasl Backend

Quantlix · Identity and access API

The backend that decides who can sign in to Wasl and what they can see: login, onboarding, sessions, tenants and permissions.

The problem

Login and permissions are where most backends leak. Wasl needed a clean contract and a login flow that doesn't trust the browser more than it should.

What I built

  • FastAPI, SQLModel and PostgreSQL, with schema changes tracked in Alembic.
  • Keycloak (OIDC) sign-in, server-side sessions in secure cookies, CSRF tokens.
  • Idempotency-Key and If-Match checks so retries and edits don't corrupt data.
  • Finished the Phase 02 onboarding module through a reviewed pull request, then tested the endpoints by hand.

AI Voice Assistant for Document Q&A

Voice-driven RAG

Ask a question about a PDF out loud and hear the answer, from a backend that serves many users at once.

The problem

Voice tools usually run as single-session scripts. This one needed to behave like a real service: background jobs, stored state and authentication.

What I built

  • FastAPI with Postgres for state and Qdrant for vector search.
  • Redis and Celery run transcription, retrieval, answering and speech as background jobs.
  • faster-whisper for speech in, Groq LLaMA 3.3 70B for answers from retrieved text only, Coqui TTS for speech out.
  • API-key auth, Tesseract OCR for scanned PDFs, Alembic migrations.
